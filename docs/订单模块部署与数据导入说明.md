# 订单中心模块 - 部署与数据导入说明

> 更新日期：2026-10-09
> 适用项目：`D:\myCode\huiyi\huiyi-console-tpl`（生产环境 https://www.geeksdom.com.cn/）

## 1. 模块概览

```
四平台拉取脚本(本机, 每日定时)
        │
        ▼
backend/scripts/import-orders.js   ← 字段映射 + 状态归一化 + 幂等入库
        │
        ▼
MySQL orders 表（UNIQUE KEY: platform + order_no，重复导入自动更新为最新状态）
        │
        ▼
GET /api/orders        ← 列表（分页/筛选，不含 raw_data）
GET /api/orders/:id    ← 详情（含 raw_data 完整原始数据）
        │
        ▼
前端 订单管理页 /orders（关键字段列表） + /orders/:id（分类详情页）
```

**数据源与路径**（换机器时改 `import-orders.js` 顶部 `PATHS`）：

| 平台 | 数据路径 | 更新方式 | 更新时间 |
|---|---|---|---|
| Shopify | `D:\myCode\huiyi\DataSync\shopify\data\日期\` | TRAE 定时任务 | 每天 09:30 |
| 聚水潭 | `D:\TraeWork Data\聚水潭订单拉取\data\日期\orders_raw.json` | Windows 计划任务 | 每天 08:30 |
| 1688 | `D:\myCode\huiyi\DataSync\alibaba1688\data\日期\` | Windows 计划任务「1688每日同步」 | 每天 09:20 |
| 天猫 | `D:\TraeWork Data\天猫手动导出\ExportOrderList*.xlsx` | 后台手动导出放入即并入 | 手动 |

**订单状态归一化**（`status_code` 列）：

| status_code | 含义 | 判断口径 |
|---|---|---|
| pending | 待付款 | 聚水潭/天猫"等待买家付款"；Shopify 财务状态 PENDING |
| paid | 待发货 | 平台"等待卖家发货"；Shopify 已付款未发货 |
| shipped | 已发货 | 平台"等待买家收货/已发货"；Shopify 已履约未关闭 |
| completed | 已完成 | 平台"交易成功"；Shopify 已履约且已关闭 |
| cancelled | 已取消 | 平台"交易取消/关闭"；Shopify 有取消时间 |
| other | 其他 | 无法归类的平台原始状态 |

## 2. 数据导入（本机执行）

```bash
# 全量导入（扫描所有日期目录 + 天猫手动导出，幂等可重复执行）
node backend/scripts/import-orders.js

# 只导入最近 N 天的每日数据（天猫除外，始终全量）
node backend/scripts/import-orders.js --days=3

# 只导入指定平台
node backend/scripts/import-orders.js --source=shopify,jushuitan
```

- **每日自动导入**：TRAE 定时任务「订单数据每日导入」每天 10:30 执行（在 08:30 聚水潭、09:20 1688、09:30 Shopify 拉取之后）。
- **天猫订单**：从天猫后台手动导出 `ExportOrderList*.xlsx`，放入 `D:\TraeWork Data\天猫手动导出\`，下次导入自动并入（无需删旧文件，按订单编号幂等）。
- **导入验证**：后端启动后运行 `node backend/scripts/smoke-orders.js`，校验列表/筛选/详情接口。

## 4. 生产部署步骤（geeksdom.com.cn 服务器）

1. **同步代码**：将 `backend/` 与 `frontend/` 最新代码上传服务器。
2. **建表**（服务器上执行一次）：
   ```bash
   cd backend && npm install
   node scripts/migrate-orders.js     # 创建 orders 表（含 raw_data JSON 列）
   ```
   无 DB 环境变量时脚本自动使用 `config/db.js` 的默认值，与 `ecosystem.config.js` 生产配置一致。
3. **重启后端**：`npm run restart`（即 `pm2 restart huiyi-backend`）。
4. **构建前端**：`cd frontend && npm install && npm run build`，dist 按现有方式交给 nginx。
5. **验证**：登录系统 → 订单管理，列表应显示订单数据；Nginx 无需新增规则（`/api` 反代已存在）。

## 5. 生产数据从哪来（重要）

导入脚本在本机运行，当前写入**本机 MySQL `huiyi_test`**。要让生产站点展示订单，二选一：

**方式 A（推荐）：本机导入直连生产库**
1. 服务器 MySQL 创建远程用户（仅授予 orders 表 SELECT/INSERT/UPDATE，强密码）。
2. 云服务器安全组/宝塔防火墙放行 3306，来源 IP 限制为本机公网出口 IP。
3. 本机 `backend/.env` 修改：
   ```
   DB_HOST=服务器IP
   DB_USER=远程用户
   DB_PASSWORD=远程密码
   DB_NAME=console-backend
   ```
4. 每日 10:30 的导入任务无需任何改动，自动写入生产库。

**方式 B：拉取脚本整体迁到服务器**（长期方案）：数据拉取、导入都在服务器执行，本机不再参与。

**方式 C：手动导出 .sql 上传宝塔**（无需开放 3306 端口）：

**已自动化**：每日 10:30 的「订单数据每日导入」任务在导入完成后会自动执行 `backend/scripts/export-orders-sql.js`，把当天全量快照写到：
```
D:\TraeWork Data\宝塔订单SQL导出\orders_YYYY-MM-DD.sql
```
（脚本自带行数与中文编码校验，自动清理 30 天前的旧快照）。**你只需要随时拿这个目录里最新的文件去宝塔导入即可**。手动补一次快照也是同一条命令：`node backend/scripts/export-orders-sql.js`。

本机导出（PowerShell，Windows 服务 MySQL 8.0 路径）：
```powershell
$dump = "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe"
$out  = "D:\TraeWork Data\orders_上传宝塔_$(Get-Date -Format yyyyMMdd).sql"
Start-Process -FilePath $dump -ArgumentList '--user=root','--password=本机密码','--host=127.0.0.1',
  '--default-character-set=utf8mb4','--single-transaction','--set-gtid-purged=OFF',
  '--no-tablespaces','--skip-comments','huiyi_test','orders' `
  -RedirectStandardOutput $out -NoNewWindow -Wait
```
说明：
- 导出含 `DROP TABLE IF EXISTS` + `CREATE TABLE` + 全量数据，**重复导入即整体覆盖**，服务器无需先跑 migrate。
- 上传：宝塔面板 → 数据库 → `console-backend` → 导入 → 上传该 .sql（或 phpMyAdmin 导入）。无需开放 3306。
- 这是**快照**：每天新增数据只在本地库，需定期重新导出上传才会更新到服务器；要自动化请走方式 A。
- 注意 PowerShell 管道方式（`| Out-File`）会破坏中文，必须用 `Start-Process -RedirectStandardOutput`。
- 服务器 MySQL 需 ≥5.7（orders 表含 JSON 列）。

**方式 C-2：每日增量文件（已自动化，日常推荐）**

每天 11:00 TRAE 定时任务「订单增量SQL每日导出」执行 `backend/scripts/export-orders-daily.js`，把**当天新入库/有更新的订单**写到：
```
D:\myCode\huiyi\DataSync\orders_daily_YYYY-MM-DD.sql
```
- `REPLACE INTO` 幂等写法，**可安全重复导入**；不含 DROP/CREATE，不会清空线上已有数据。
- 按"当日拉取"节奏每天导一个文件即可把线上数据追平；文件按日期命名，保留 30 天。
- 补导指定日期：`node backend/scripts/export-orders-daily.js 2026-10-05`。
- 与全量快照分工：**日常追加用增量文件**，灾难重建/整库覆盖用全量快照（`orders_YYYY-MM-DD.sql`）。
- 前提：本机 MySQL80 服务需运行中（管理员执行 `net start MySQL80`）。

## 6. 常见问题

| 问题 | 说明 |
|---|---|
| 聚水潭 TRAE 任务（DataSync\jushuitan）拉取失败 | IP `183.12.66.246` 不在聚水潭白名单，需到聚水潭开发者后台添加；当前导入不受影响（数据源是 TraeWork 的聚水潭订单拉取目录） |
| 某平台当天没有数据目录 | 正常（当天订单次日早晨才拉取），导入自动跳过 |
| 重复执行导入 | 安全。唯一键 platform+order_no，重复导入等于"更新为最新状态" |
| 退款/取消订单 | 重新拉取后导入即可覆盖状态，无需手工处理 |
